# Task: 左侧资料可直接查看授权原文

## 问题

当前左侧只显示知识节点名称和片段数量，不能打开对应原始文件；现有字号也偏小。用户希望从左侧直接查看文件，同时整体字体稍微增大。

## 范围

- 包含：真实知识节点显示文件类型和更新时间；点击后加载授权原文预览；提供原始导出文件下载；桌面与移动预览界面；整体字号上调；API、ACL 和 payload 测试。
- 不包含：在线编辑；Office 原格式逐像素渲染；ZIP 在线展开；OCR；钉钉在线预览服务。

## 验收标准

- [x] 正常行为：左侧文件可点击，应用内显示按页/章节提取的原文，并可下载原始导出文件。
- [x] 身份/ACL/隐私行为：服务端按稳定用户 ID 校验；无权文件的预览与下载返回相同安全错误，不泄漏存在性。
- [x] 失败行为和 payload 上限：拒绝路径穿越、缺失文件、超大下载和超长预览；前端显示稳定错误状态。
- [x] 桌面端和移动端字号、文件树与预览可用。

## 约束

- 相关产品不变量：无权原文不得进入响应或前端；回答引用和文件预览均以当前授权版本为准。
- 相关架构边界：Controller 只依赖 Service 接口；原文件路径由服务端配置和受控元数据解析。
- 需要保留的无关工作区修改：真实 Embedding、导入器、钉钉 TODO、Docker 和现有问答体验。

## 验证

- 单元/契约测试：31 个 Spring 测试通过，覆盖授权预览/下载、无权拒绝、共享 ZIP 整包下载拒绝、路径穿越和预览上限；9 个 Vue 测试通过，包含左侧文件打开预览。
- RAG 离线评测：3 个固定用例全部通过，越权文档和禁止术语泄漏率为 0。
- 手工/集成证据：Docker 中三个真实节点分别返回 7 页、14 节和 8 页原文；三个原文件下载均返回 200，类型与字节数一致；桌面 1280×720 和移动 390×844 页面检查通过。
- 统一命令：`powershell -ExecutionPolicy Bypass -File scripts/verify.ps1`

## 交付

- 决策：左侧节点直接表示导入源文件；点击后打开只读文本预览抽屉，PPTX 按页、Markdown 按章节显示；原文件使用独立授权下载接口。共享原包只有在其中全部文档均授权时才允许下载。
- 数据读取/写入与日志：只读 JSONL 与 `data/knowledge/raw/`；响应最多返回 50,000 字符，下载最大 50 MiB；普通日志不记录原文、文件内容或完整路径。
- 剩余风险：当前是提取正文预览，不复刻 PowerPoint 原始版式；纯图片页仍需 OCR；生产部署应将原文件迁移到对象存储并使用短时授权链接。
- 延后工作：Office 原版在线渲染、OCR、钉钉官方预览与生产对象存储。
