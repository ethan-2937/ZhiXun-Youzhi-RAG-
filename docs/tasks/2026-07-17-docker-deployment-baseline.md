# Task: 建立 Docker 本地运行与服务器部署基线

## 问题

MVP 已可分别启动 Spring 和 Vue，但缺少与服务器一致的容器化运行方式。需要让开发阶段可在本机一键启动，并为后续钉钉 HTTPS 部署保留明确边界。

## 范围

- 包含：Spring 多阶段镜像、Vue/Nginx 多阶段镜像、同源 API 代理、Compose 编排、健康检查、环境变量样例和部署说明。
- 不包含：真实服务器操作、域名与证书申请、镜像仓库、数据库/Redis/MinIO、生产钉钉凭据和多实例发布。

## 验收标准

- [x] `docker compose up --build -d` 可启动前后端，并通过 `127.0.0.1:18080` 单一 HTTP 入口访问。
- [x] 后端不直接暴露宿主机端口，浏览器只通过 Nginx 同源访问 `/api`。
- [x] 镜像不包含本地依赖、构建产物或凭据，运行进程不使用 root。
- [x] 请求体、代理超时、只读文件系统和健康检查有显式配置。

## 约束

- 相关产品不变量：Session/CSRF 保持同源；生产钉钉模式失败关闭；所有 payload 有上限。
- 相关架构边界：Nginx 只提供静态页面和反向代理，不承担身份或 ACL 裁决。
- 需要保留的无关工作区修改：现有 MVP、钉钉认证切片和 Harness。

## 验证

- 单元/契约测试：由统一验证脚本运行现有 Spring、Vue 和 Harness 测试。
- RAG 离线评测：继续使用完全虚构的固定数据集。
- 手工/集成证据：Docker Compose 实际构建前后端镜像并达到 `healthy`；宿主机入口完成首页、健康检查、CSRF、演示 Session、当前用户和受保护 workspace 冒烟；容器 UID 分别为前端 101、后端 100。
- 统一命令：`powershell -ExecutionPolicy Bypass -File scripts/verify.ps1`

## 交付

- 决策：Vue 静态站点与 Spring 分为两个镜像；Nginx 统一暴露页面和 `/api`，服务器 TLS 由外层入口代理终止。
- 数据读取/写入与日志：当前容器无业务持久卷；Nginx 标准输出只记录方法、无查询参数的 URI、状态、字节数和耗时，并跳过健康检查，不记录请求体、Cookie、身份或凭据。
- 剩余风险：真实 HTTPS、钉钉端内、镜像仓库和服务器资源上限尚未验证；当前单实例 Session 和免登码防重放记录仍未迁移 Redis。
- 延后工作：数据库、Redis、对象存储、集中日志、镜像仓库和滚动发布。
