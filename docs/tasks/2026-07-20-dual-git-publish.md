# Task: 首次发布并固化双远端同步

## 问题

当前工作区尚未初始化 Git。用户要求将项目首次上传到 GitHub 与阿里云 Codeup，并在后续开发完成后自动同步两个代码库。

## 范围

- 包含：发布前隐私审计；初始化 `main`；创建首个提交；配置 `origin`/`codeup`；推送两个远端；增加可复用发布脚本与仓库约定。
- 不包含：CI 自动部署、GitHub Actions 发布、强制推送、远端分支保护和凭据管理。

## 验收标准

- [x] `.env`、`data/`、真实资料、构建产物和依赖目录不进入首个提交。
- [x] `scripts/verify.ps1` 在发布前通过。
- [x] GitHub 与 Codeup 的 `main` 指向同一个提交。
- [x] 后续发布脚本在脏工作区、敏感路径被跟踪或验证失败时拒绝推送。

## 约束

- 相关产品不变量：生产凭据和真实内部资料不进入 Git。
- 相关架构边界：发布流程不改变应用运行时架构。
- 需要保留的无关工作区修改：当前工作区全部是首次项目内容，但仍按 `.gitignore` 排除本地数据和产物。

## 验证

- 单元/契约测试：统一 Harness、31 个 Spring 测试、9 个 Vue 测试和 16 个 Python 测试通过；发布脚本完成干净工作区和跟踪路径审计。
- RAG 离线评测：沿用统一验证中的固定评测。
- 手工/集成证据：首个提交 `7453484` 已推送到 GitHub `origin/main` 与 Codeup `codeup/main`；最终记录提交再次通过双远端脚本同步。
- 统一命令：`powershell -ExecutionPolicy Bypass -File scripts/verify.ps1`

## 交付

- 决策：仅推送已提交且工作区干净的当前分支；发布脚本先验证，再顺序推送 `origin` 与 `codeup`。
- 数据读取/写入与日志：读取 Git 索引、工作区状态和测试输出；只写 Git 元数据及两个远端，不上传被忽略文件。
- 剩余风险：两个独立远端无法形成原子事务，第二个远端失败时需要重试恢复一致。
- 延后工作：分支保护、CI 双镜像、发布标签和自动部署。
