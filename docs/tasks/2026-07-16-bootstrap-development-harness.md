# Task: 建立钉钉 RAG 项目的开发 Harness

## 问题

新仓库只有系统方案，没有统一开发入口、机械质量门或 RAG 回归契约。参考 `D:\weekly_report` 后，需要保留其短仓库地图、隐私失败关闭、复杂度棘轮和统一验证思想，同时针对在线知识问答增加 ACL 与引用评测。

## 范围

- 包含：仓库规则、质量/隐私文档、静态检查、复杂度预算、RAG JSONL 契约、确定性评分器、虚构夹具、单元测试、统一 PowerShell 验证和 CI。
- 不包含：Spring/Vue 业务脚手架、真实钉钉调用、真实模型评测、生产知识或员工问题。

## 验收标准

- [x] 正常行为：一个命令完成当前所有可用检查。
- [x] 身份/ACL/隐私行为：敏感路径、凭据形态、禁止来源和禁止术语有硬门槛。
- [x] 失败行为和 payload 上限：缺文件、超预算、非法 JSONL、重复/缺失用例和超大输入均失败。
- [x] Spring/Vue 目录尚不存在时明确跳过，出现后自动进入验证。

## 约束

- 相关产品不变量：稳定钉钉身份、ACL 前置、带引用回答、无依据拒答。
- 相关架构边界：Controller 不直连 Mapper/Repository/具体 Service/向量或模型客户端。
- 需要保留的无关工作区修改：已有 `docs/DINGTALK_RAG_DEVELOPMENT_PLAN.md`。

## 验证

- 单元/契约测试：`python -m unittest discover -s tests -p "test_*.py"`，10 项通过。
- RAG 离线评测：3 个完全虚构用例；覆盖、可回答性、来源召回、术语覆盖均为 1.0；两项泄漏率为 0；P95 为 910 ms。
- 统一命令：`powershell -ExecutionPolicy Bypass -File scripts/verify.ps1`。
- Spring/Vue：目录尚未创建，统一脚本明确跳过，不伪造通过结果。

## 交付

- 决策：采用“开发质量门 + RAG 离线评测”双层 Harness；权限泄漏不允许被平均指标抵消。
- 数据读取/写入与日志：只读取仓库契约和虚构夹具；不访问网络或外部服务；错误只输出安全错误码和位置。
- 剩余风险：当前样例仅验证 Harness 自身，不代表未来 RAG 质量；业务代码出现后必须加入认证、ACL、删除一致性和集成测试。
- 延后工作：创建 Spring/Vue 脚手架后收紧必需文件、测试和部署配置检查；获得经批准的脱敏语料后建立正式评测基线。
