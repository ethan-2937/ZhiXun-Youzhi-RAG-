# 质量策略

## 两层 Harness

1. 开发质量 Harness：检查仓库地图、必需契约、敏感路径、复杂度预算、架构依赖和测试入口。
2. RAG 离线评测 Harness：验证固定数据集和预测格式，计算可回答性、引用召回、越权引用、关键词覆盖、泄漏和延迟指标。

统一入口：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/verify.ps1
```

## 测试优先级

1. 无权文档在检索、上下文、答案、引用和缓存中的零泄漏。
2. 免登码过期/重放、错误组织、停用用户和身份不确定时的拒绝路径。
3. 删除、撤回、版本切换和权限变更后的索引一致性。
4. Prompt Injection 文档、恶意文件、超大 payload、超长对话和模型超时。
5. 引用正确性、无依据拒答、混合检索和 Reranker 回归。
6. PC/Android/iOS 钉钉端内登录、SSE 断连和来源打开。

## 复杂度棘轮

`harness/quality-baseline.json` 中的默认行预算约束新增文件。只有已有热点才允许精确豁免；触碰热点时应提取模块并逐步下调预算，而不是扩大豁免。

## RAG 评测规则

- 固定集只使用经批准的脱敏或虚构问题；生产问题不得自动复制到 Git。
- 每个用例明确主体、知识范围、可回答性、必需来源、禁止来源和关键术语。
- 权限泄漏是硬失败，不能被平均准确率抵消。
- 修改分块、Embedding、检索、重排、Prompt 或模型后，必须与固定基线比较。
- LLM-as-judge 只能作为补充；ACL、引用 ID、覆盖率和 payload 上限使用确定性检查。
